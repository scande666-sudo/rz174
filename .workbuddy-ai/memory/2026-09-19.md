### ГРАБЛИ: PortableGit переписывал переводы строк

- В `.../PortableGit/versions/1.2.0/etc/gitconfig` стоит `core.autocrlf=true` → git предупреждал
  «LF will be replaced by CRLF» и при следующем касании переписал бы файлы сайта.
- Лечение: `.gitattributes` с `* text=auto eol=lf` + локальный `core.autocrlf=false`.
  Проверка: `grep -c $'\r' "наш сайт/index.html"` → 0.
- **На ноутбуке после клонирования проверить то же самое** — если там PortableGit с autocrlf=true,
  а `.gitattributes` в репозитории есть, всё будет ок, но убедиться стоит.

### ГРАБЛИ: порт 22 закрыт, SSH не проходит

- `ssh -T git@github.com` → `connect to host github.com port 22: Connection timed out`.
  HTTPS при этом открыт (`github.com` → 200), а `ssh.github.com:443` отвечает.
- **Лечение:** `~/.ssh/config`:
  ```
  Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
  ```
  После этого `git@github.com` отвечает `Permission denied (publickey)` — то есть связь есть,
  осталось только зарегистрировать ключ. **Проверка на будущее:** таймаут = порт закрыт,
  `Permission denied` = маршрут ок.
- Ключ: `~/.ssh/id_ed25519` (ed25519, без пароля), публичная часть — `~/.ssh/id_ed25519.pub`.
  Отпечаток начинается с `ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIBV3Z2FAD1GF8bGuDRhPJ+nKUj0VfDPkzcZ1caGJCfWA`.
- `ssh-keyscan` в этой среде не сработал (порт 22 недоступен) — известный хост добавился сам
  через `StrictHostKeyChecking=accept-new`.
- На ноутбуке, скорее всего, та же история с портом 22 → тот же `~/.ssh/config` пригодится.
